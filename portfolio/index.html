01

AWS Secure VPC

How it works

A production-hardened multi-AZ VPC provides the secure network foundation for all other projects. Public subnets host the Bastion EC2 and Internet Gateway, while private subnets hold application EC2 instances. All traffic between subnets is governed by stateless NACLs and stateful Security Groups.

VPC Flow Logs capture accepted and rejected traffic separately, feeding into CloudWatch metric filters that detect SSH brute-force attempts and port-scan patterns. SNS alerts trigger immediately when anomalous thresholds are breached.

  • Dual-layer firewall: stateless NACLs + stateful Security Group referencing (no broad 0.0.0.0/0 ingress)
  • VPC Flow Logs split into accepted/rejected streams — faster CloudWatch Insights queries
  • CloudWatch metric filters with SSH brute-force alarm: >5 failed attempts / 5 min
  • Bastion with SSH agent forwarding — private key never touches the Bastion disk
  • All resources tagged with environment, owner, and cost-centre for audit compliance
  • Terraform remote state in S3 with DynamoDB locking — safe for team use

02

GuardDuty Threat Detection & Auto-Remediation

How it works

When GuardDuty raises a finding, EventBridge routes it to a Lambda remediation function. An EventBridge rule filters findings with severity above 7.0 to avoid alert fatigue, forwarding only HIGH and CRITICAL findings. The Lambda then fans out to four parallel remediation actions.

Each action is individually toggled via environment variable feature flags, so teams can enable only what their runbook approves. All actions are idempotent and designed to run safely if triggered twice.

  • EC2 quarantine: replaces all instance security groups with a zero-ingress/zero-egress isolation SG
  • IAM credential revocation: disables access key and attaches an inline DenyAll policy to the role
  • Forensic EBS snapshot created for all attached volumes before any destructive action
  • Severity filter on EventBridge rule: only severity > 7.0 triggers Lambda (configurable)
  • Dual-channel alerting: SNS topic (email/PagerDuty) + Slack webhook with structured finding JSON
  • 73 pytest + moto unit tests covering all severity bands, feature flags, and error paths

AWS Inspector v2 — CVE Scanning

How it works

Inspector v2 continuously scans EC2 instances via the SSM Agent — no open inbound ports required. Findings are streamed to EventBridge, which filters HIGH and CRITICAL severity CVEs and triggers a Lambda remediation function.

The Lambda tags the affected EC2 instance with structured metadata (severity band, CVE ID, finding type, CVSS score, last-scanned timestamp) and publishes an SNS alert to the operations team. All five severity bands are mapped, and the max CVSS score is extracted from multiple scoring vectors per finding.

  • Zero open ports: Inspector v2 uses SSM Agent for agent-based scanning (no network exposure)
  • EC2 instance tagging: severity, CVE-ID, finding-type, CVSS score, last-scanned ISO timestamp
  • Severity band mapping across all 5 tiers: CRITICAL, HIGH, MEDIUM, LOW, INFORMATIONAL
  • Max CVSS score extracted from all available scoring vectors per finding
  • SNS alert with structured finding payload for PagerDuty or email delivery
  • 27 pytest + moto unit tests: all severity bands, missing fields, and pagination edge-cases

04

AWS WAF — Web Application Firewall

How it works

WAFv2 sits in front of an API Gateway HTTP API, inspecting all inbound requests against five managed and custom rule groups. Requests that match threat patterns are blocked before they reach application code. All blocked and allowed requests are logged to CloudWatch for analysis and dashboarding.

API Gateway was chosen over an ALB specifically to avoid the ~$18/month fixed ALB cost at demo volumes — the WAFv2 capability is identical. WAF logs go directly to CloudWatch (avoiding Kinesis Firehose's ~$10/mo baseline at low volume).

  • AWSManagedRulesCommonRuleSet (OWASP core): blocks common web attack vectors
  • AWSManagedRulesSQLiRuleSet: SQL injection pattern detection and blocking
  • AWSManagedRulesKnownBadInputsRuleSet: blocks Log4Shell, SSRF, and shellcode patterns
  • Rate-based rule: 2,000 requests per 5-minute window per source IP
  • Custom IP set blocklist: operator-managed, updated without redeployment via Terraform variable
  • 33 pytest unit tests: all rule groups, rate logic, IP set operations, and CloudWatch metric filters
Monthly cost (demo) ~$6 / mo

05

AWS Macie + KMS — PII Classification

How it works

Macie v2 runs weekly scheduled classification jobs against the sensitive S3 bucket, using both AWS managed identifiers and two custom identifier patterns (AWS account numbers, internal employee ID format). Findings are routed through EventBridge to a Lambda that performs the quarantine action.

The Lambda copies flagged objects to an isolated quarantine bucket, deletes the original, and tags the copy with finding metadata (severity, finding type, Macie job ID). A single KMS Customer-Managed Key with annual auto-rotation encrypts all buckets — reducing cost from $4/mo to $1/mo versus per-bucket keys.

  • Weekly scheduled scans instead of continuous monitoring — ~10x cheaper at demo-scale S3 volumes
  • Custom Macie identifiers: regex patterns for AWS account numbers and employee ID format
  • Quarantine action: copy → tag with finding metadata → delete original (idempotent)
  • Single rotating KMS CMK for all buckets: $1/mo vs $4/mo for four separate keys
  • Quarantine bucket blocks all public access and enforces KMS encryption at rest
  • 36 pytest + moto tests covering all finding severities, quarantine logic, and KMS key rotation
Monthly cost (demo) ~$3 / mo
